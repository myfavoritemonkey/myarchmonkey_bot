# myarchmonkey_bot

Личный Telegram-бот для запуска локального Codex CLI на этом Arch Linux ПК. Сообщения принимает только из разрешённого личного чата. Бот отправляет подтверждение, а после выполнения — итоговый ответ и подготовленные файлы. Одновременно выполняется одно задание.

## Настройка

1. Создайте бота у [@BotFather](https://t.me/BotFather).
2. Впишите токен и свой **числовой** Telegram user ID в `config.toml`. Узнать ID можно через [@userinfobot](https://t.me/userinfobot) или другой доверенный способ. Не отправляйте токен в чат и не публикуйте `config.toml`.
3. Проверьте `working_directory` и `codex_path` в `config.toml`. `working_directory` задаёт папку, файлы которой Codex будет читать. Рабочей папкой для записи служит `temp/` внутри проекта бота.
4. Убедитесь, что `codex login status` показывает действующий вход.

```bash
cd /home/pc/my/projects/myarchmonkey_bot
cargo build --release
cargo run --release
```

Напишите боту в личном чате, например: «Посмотри файлы журнала и выведи оценки Иванова Ивана Ивановича, указав класс и даты». Бот игнорирует всех остальных отправителей и сообщения из групп.

Команда `/status` показывает текущую задачу, время её работы, модель, выбранную папку и количество ожидающих файлов. Команда `/cancel` прерывает выполняемую задачу Codex. Во время выполнения бот продолжает принимать команды; новое текстовое задание нужно отправить после завершения или отмены текущего.

Команда `/project` открывает проводник папок с кнопками. Можно подниматься к корню файловой системы, открывать вложенные каталоги и выбрать текущую папку для следующих заданий. Смена папки очищает контекст диалога. Путь сохраняется в `state.json`; уже выполняемая задача продолжает работать с ранее выбранной папкой.

Команда `/model` показывает список моделей с кнопками. Нажмите нужную модель, и бот сохранит выбор в `state.json`. Следующие задания будут запускаться с этой моделью; текущую модель показывает галочка. Список соответствует меню установленного Codex CLI на момент создания бота. Если после обновления CLI список изменится, обновите константу `MODELS` в `src/main.rs`.

Бот сохраняет текст последних восьми заданий и ответов в `state.json` и передаёт его Codex как контекст следующего задания. Для каждого сообщения Codex всё ещё запускается в отдельной сессии. Команда `/reset` очищает сохранённый диалог и ожидающие файлы, а также останавливает текущую задачу. Выбранные модель, проект и папки `temp/` остаются на месте.

Отправьте документ или фотографию с подписью-заданием — бот скачает файл и передаст его Codex. Если отправить файл без подписи, можно прислать задание следующим сообщением. Несколько файлов можно отправить по одному без подписи, затем написать общее задание. Telegram Bot API разрешает скачивать файлы не больше 20 МБ; бот принимает до 10 файлов на задание.

Для каждого задания бот создаёт уникальную папку вида `temp/task_22_11_2026-10_30/` по местным дате и времени. При совпадении минут добавляется `_2`, `_3` и так далее. Входные файлы находятся в `inputs/`, черновики Codex может хранить рядом, а итоговые файлы должен складывать в `outputs/`. Бот отправляет через Telegram только файлы из `outputs/`. Папка задания остаётся на диске после отправки. Бот пропускает скрытые файлы и символические ссылки; за один раз отправляет до 10 файлов размером не более 20 МБ каждый. На этом ПК доступны `pdftotext`, `libreoffice`, `pandoc`, `typst` и `gs` для работы с PDF.

## Автозапуск через systemd

После сборки и настройки `config.toml`:

```bash
systemctl --user link /home/pc/my/projects/myarchmonkey_bot/myarchmonkey_bot.service
systemctl --user enable --now myarchmonkey_bot.service
systemctl --user status myarchmonkey_bot.service
```

Чтобы пользовательская служба работала и без открытого сеанса входа в систему, администратор может выполнить `sudo loginctl enable-linger "$USER"`.

## Ограничения

- Codex запускается с `--sandbox workspace-write`, но его рабочая папка находится внутри `temp/task_<дата>-<время>/`. Остальные файлы, включая файлы выбранного проекта, находятся вне области записи Codex. `--ask-for-approval never` запрещает запрашивать расширение прав, а `--ignore-user-config` исключает дополнительные области записи из пользовательского конфига Codex. Дополнительно отключена запись в `/tmp` и `$TMPDIR` как в отдельные корни песочницы.
- Для каждого сообщения создаётся новая сессия Codex. Контекст из `state.json` передаётся в запрос текстом; внутренние шаги и вызовы инструментов предыдущей сессии не сохраняются. Текст каждой стороны одного обмена ограничен 3000 символами.
- Telegram и сервис модели получают данные, которые вы отправляете или которые Codex включает в ответ. Учитывайте это при работе с персональными данными учеников.
- `config.toml`, `state.json` и содержимое `temp/` исключены из Git. Токен хранится только локально. После ввода токена ограничьте права командой `chmod 600 config.toml`.
